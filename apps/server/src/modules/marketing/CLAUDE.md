# marketing module

Promo codes «أكواد الخصم» (architecture §4.2; AP §9.11.1). Banners, home sections and mass pushes (AP §9.11.2–9.11.4) come with 2.27.

## Rules

- **What this module owns:** `marketing.promo_codes` and `marketing.idempotency_keys`. Cities, restaurants, zones and admin accounts are plain ids.
- **A code (`promo-codes.ts`, the pure rules; slice 2.21a):** one row per code, upper-case Latin letters and digits, 3 to 20, unique in the city (`promo_codes_city_code`; a typed code is trimmed and upper-cased, `normalizeCode`). `kind` `percentage` (`percent_bp` 1 to 10000, an optional cap `max_discount`), `fixed_amount` (`amount`) or `free_delivery` (no value: the whole fee). The minimum order is on the items value before discounts. `valid_from` before `valid_to`; optional hours `start_minute`/`end_minute` on the city clock, both or neither, an end at or before the start running past midnight. `total_limit` and `per_customer_limit` (null: none, the second never above the first). `audience` `everyone` or `new_users`. `restaurant_ids` and `zone_ids` (none: all), checked against the city (`MerchantsService.restaurantIds`, `GeoService.zones`). `funding` `platform`, `restaurant` or `shared`, kept as `merchant_share_bp` (0, 10000, or the ratio 1 to 9999); a code a restaurant funds names its restaurants, since each pays its share on Saturday (AP §8.4; decided by us). `daily_budget` (null: none) counts the business day of the daily report (owner decision 2026-11-16). `visibility` `visible` or `secret`. `checkPromoFields` and the table's `CHECK`s say the same. Amounts are in the city's base when saved (`currency`), under `lockCityCurrencies` (`409 no_base_currency` without one); registered with `FxService.useCityAmounts` while a code has not ended.
- **Status:** `active` or `paused`, set by OWN. What the list shows (`promoCodeState`): `expired` from `valid_to`, else `paused`, else `scheduled` before `valid_from`, else `active`. The daily budget's pause is worked out from the day's cost (2.21b), never stored.
- **A batch:** `count` (2 to 500) codes of the prefix (up to 8 letters and digits) and 8 random characters that cannot be misread (`generatedCode`, no 0, O, 1, I or L), drawn again on a collision, sharing a `batch_id`, created in one transaction under the city's advisory lock `marketing.codes:<cityId>`, as a typed code is.
- **Keys (architecture §5.3):** creating one code or a batch takes `Idempotency-Key`: `idempotency_keys` per admin account with a hash of the command and the codes created, checked again under the key's advisory lock; a repeat within 24 hours answers those codes, another command with the key `422 idempotency_key_reused`. The edit, pause and resume set a value, so no key.
- **Audit:** `promo_code.create` (target the code), `promo_code.generate` (target the batch), `promo_code.edit` (before and after), `promo_code.pause`, `promo_code.resume`.
- **Admin routes (`admin-promo-codes.controller.ts`, AP §6):** `GET /v1/admin/promo-codes?cityId=` (`marketing.read`: OPS, `marketing.read_costs`: FIN, or `marketing.manage`: OWN) answers the codes newest first with the city's restaurants, zones and base currency, and `canManage`; `costToDate` is null without `marketing.read_costs` or `marketing.manage`. `POST /v1/admin/promo-codes` (one typed code), `POST …/batch`, `PUT …/{codeId}` (every field but the code), `POST …/{codeId}/pause` and `…/resume` (`marketing.manage`, each with `{ cityId }` in the body). `400 invalid_promo_code` with the rule broken, `404 unknown_city`, `unknown_promo_code`, `409 code_taken`, `no_base_currency`. Money travels as strings of minor units, the percentage and the ratio as basis points.
