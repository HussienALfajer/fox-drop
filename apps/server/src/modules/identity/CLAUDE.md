# identity module

Users of the four products, their sign-in and sessions (architecture §4.2). So far: the admin panel's accounts, first sign-in, sign-in and sessions (AP §5.1–5.3; architecture §10.3). Roles, guards on every route and the admin team actions are slice 0.8.

## Rules

- **Sign-in name** (owner decision 2026-11-05): an admin account has an email, a phone or both, and signs in with either. Emails are stored in lower case; phones are taken in international form only (`+` or `00`), so no country is guessed (`sign-in-name.ts`).
- **Nothing secret in clear** (architecture §10.3, §15.3): passwords are Argon2id; phones and TOTP secrets are AES-256-GCM encrypted with `IdentitySecrets` (`secrets.ts`), phones with a keyed hash to find them by; backup codes are stored as a keyed hash; setup and session tokens as SHA-256. The keys derive from `IDENTITY_ENCRYPTION_KEY` (32 bytes in base64). `identity.test.ts` reads the stored rows and the audit events and fails on any secret in clear.
- **Shown once:** the setup token only in the link the command prints, each TOTP secret only in the enrolment that made it (a new call makes a new secret), the backup codes only in the setup's answer, the session token only in the cookie. Tokens and codes travel in bodies, the cookie or a URL fragment, never in a path.
- **First OWN** by the server command only (AP §5.3): `pnpm --filter @fox-drop/server admin:create-owner --email <email>` locally, `node dist/modules/identity/create-owner-command.js --email <email> --phone <phone>` (either or both) in a deploy. It prints the link with `ADMIN_PANEL_URL`, to stdout, never to the logger. Run again with the same name while that owner is still pending, it expires the open links and prints a new one (`admin_account.setup_link_reissue`), so a lost or expired link never locks the platform out; any other case refuses.
- **Setup link:** valid 24 hours (fixed, `SETUP_LINK_HOURS`), used once, only for a pending account. The setup checks the password against `admin.password_min_length` and a TOTP code from the last secret offered, then activates the account and issues 10 backup codes in one transaction.
- **Argon2 is the costly step:** check a token or find the account before hashing, and never hash inside an open transaction except under the account's row lock, which the lockout needs.
- **Sign-in:** password and a 6-digit TOTP code or a backup code, in one request. A TOTP time step is never accepted twice (`totp_last_step`). Every refusal answers alike (`401`), except a locked account (`423`). Attempts on one account take turns on its row lock; `admin.login_max_attempts` failures lock it for `admin.lockout_min`. All settings are read at each attempt.
- **Sessions:** the cookie `__Host-fox_drop_admin` is HTTP-only, secure, same-site strict, `Max-Age` `admin.session_max_hours`. The server ends a session after `admin.session_idle_min` without activity or `admin.session_max_hours` after sign-in, read at each check, and records the reason. A route that needs a session uses `AdminSessionGuard` and `@CurrentAdminSession()` from `index.ts`.
- **Audit:** `admin_account.create`, `admin_account.setup`, `admin_account.lock`, `admin_session.sign_in` and `admin_session.sign_out`, each in the transaction of its change, with no secret in the before and after values.
- **Time:** services take `now` and never read the database clock, so tests move time by passing it.
