# files module

Uploads to the object storage and their checks before a record links them (architecture §4.2, §5.8; slice 2.5). The storage is Garage (T7); its setup and the tests' Garage are in the shared `src/storage/`.

## Rules

- **One bucket so far:** `public-media` (`PUBLIC_MEDIA_BUCKET`), served by imgproxy under `/media/` (`infra/imgproxy/imgproxy.env`). `private-docs`, encrypted and opened with short-lived signed URLs, joins with the captain documents (2.34).
- **Uploads** (`files.uploads`): `POST /v1/admin/uploads` (`{ purpose, contentType, sizeBytes }`) records an upload and answers a pre-signed `PUT` to `incoming/<uuid>.<ext>`, valid `UPLOAD_URL_SECONDS` (10 minutes). The type and the size are signed (`signableHeaders`), so Garage refuses any other body with `403`. Types: JPEG, PNG, WebP; at most `MAX_IMAGE_BYTES` (8 MB). Who may ask: `RESTAURANT_PROFILE` (`restaurants.manage` or `restaurants.create`: OWN, OPS and DATA, AP §9.6.3 step 1) for `restaurant_logo` and `restaurant_cover`, `restaurants.menus` for `item_photo` (`403` otherwise). No `Idempotency-Key`: the answer is a URL to upload with, never stored (like a secret shown once), and asking again makes another upload, of which only the linked one is used.
- **Where the panel uploads:** the URL is signed for `ADMIN_PANEL_URL`'s origin, path style (`/public-media/incoming/<file>`). nginx on the panel's host (and Vite in development, with `changeOrigin: false`) forwards that path to Garage with the same `Host`, so the signature holds and the browser needs no CORS. Uploads from the apps (2.32, 2.34) will sign for their own host.
- **Linking, in two halves:** `prepare(uploadId, purpose)` before the record's transaction, since it calls the storage and must never run under a row lock: the upload must exist (`upload_not_found`), be for that purpose (`upload_wrong_purpose`) and be at most `LINK_WITHIN_MS` (an hour) old (`upload_expired`); its file is copied from `incoming/` to its published key (`<folder>/<file>`, by purpose: `restaurants/logos`, `restaurants/covers`, `menu/items`), which no pre-signed URL covers (`upload_missing` without a file), and the copy must have the size and type asked for and start with that type's signature (`hasImageSignature`; `upload_invalid`). A file checked this way never changes again, though its upload URL still writes to `incoming/` for its 10 minutes. Then `link(tx, uploadId)` in the record's transaction takes the upload's lock and sets `linked_at`; it answers the published key, with `alreadyLinked: true` when an earlier call linked it: the caller treats the same key on the same record as a repeat and anything else as `upload_used`. A published key is new for every upload and never reused, so imgproxy's and nginx's caches never go stale.
- **The storage client** has short timeouts (2 s to connect, 10 s per request) and is built on first use from `STORAGE_URL`, `STORAGE_KEY_ID`, `STORAGE_SECRET` and `ADMIN_PANEL_URL`, so a process or a test that never uploads needs none of them. The SDK's default checksums are off (`WHEN_REQUIRED`): a pre-signed URL must not carry one the browser cannot send.
- **Tests:** `startTestStorage()` (`src/storage/test-storage.ts`) starts Garage with the image of `compose.yaml` and sets it up; point `STORAGE_URL`, the key and `ADMIN_PANEL_URL` at it before the app starts.
