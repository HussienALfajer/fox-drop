# Definition-of-done checklist (launch readiness L.1)

Every item of the four V1 definitions of done (AP §14, RA §22, CA §19, CU §19), what proves it, and its state. Audited on 2026-11-21 from `main` at `9efb0adf`: the test titles first, then the bodies of every test the title search left as a gap (nothing was run for this audit; `pnpm verify` runs every test cited here). Update a row when its gap closes, and mark it «shown on staging» when the staging rehearsal (L.10) shows it.

## How to read it

- **State:** `covered`: an automated test exercises the behaviour. `demo only`: built, but only a staging demonstration on a device shows the part that matters (ringing with the screen off, sound, real push or WhatsApp delivery, background GPS, Windows behaviour, printing); the tests named cover the logic. `gap`: not built, or part of the item has no test; the note says what is missing.
- **Gap kind:** `build` means the feature or part of it is not built; `test` means it is built and no test asserts that part (checked in the test bodies, not only the titles).
- **Who and where:** every item must also be shown on staging (each definition of done says so). The owner runs every demonstration alone on their own devices (owner decision 2026-11-21): the Android phone, the iPhone through TestFlight once the Apple Developer account exists, the Windows PC, and a browser for the panel and the portal. The run books live in `docs/runbooks/`.
- **Paths:** `server/` is `apps/server/src/modules/`; `admin/`, `portal/`, `customer/`, `captain/` and `merchant/` are `apps/admin/`, `apps/merchant-portal/`, `apps/customer/`, `apps/captain/` and `apps/merchant/`. A test is its file › its title (long titles cut with «…»).
