# packages/core_ui

## Theme (D.7)

- `FoxThemeData` maps `core_tokens` to Flutter types: `FoxColorScheme` (every colour token as a `Color`), `FoxButtonTheme` (heights, inline padding, gap, radius, focus ring and every variant's colours), `FoxTextTheme` (each `TypeScale` role as a `TextStyle` in `FoxFont.family`, `leadingDistribution: even`, the weight from the token; `number` adds tabular figures), `FoxShadows` (`BoxShadow`s), the durations and `easing` (`FoxEasing.standard` as a `Cubic`).
- `.phone()` is `FoxColors.light` with `FoxType.phone` (customer and merchant); `.captain()` is `captainLight` with `FoxType.captain`. Light only: dark copies light until it is designed (§9.2).
- `FoxTheme` is an `InheritedWidget`; `FoxTheme.of` throws a `FlutterError` naming the fix when no theme is above. No Material `ThemeData`: the apps still use Material until their screen slices, and `core_ui` never reads it.
- Tests (`test/theme_test.dart`): every field equals its token, for both themes.

## Icon (D.7)

- `FoxIcon(FoxIconData icon, {size, label, color})`. The icon is the token value itself (`FoxIcons.back`), not a name enum: `core_tokens` already generates one constant per icon, and a second enum would have to be kept in step. `FoxIconSize` is `sm` 16, `md` 24, `lg` 32.
- A `CustomPainter` draws the icon's SVG paths scaled from the 24 grid, stroke 2 at 24, round caps and joins, in `color`, else the `DefaultTextStyle` colour, else `onSurface`. `lib/src/icon/path_data.dart` parses the path data (M L H V C S Q T A Z, absolute and relative; extra pairs after M are L; S and T reflect the last control point; A goes through `arcToPoint`, a zero radius is a line); parsed paths are cached.
- `mirror` icons (`back`, `car`, `motorcycle`) flip under RTL. Without a label the icon is excluded from semantics; with one it is an image with that label.
- Tests: every icon parses and its sampled outline (path metrics, not `getBounds`, which counts control points) lies inside 2..22; one hand-checked path per command; only the three mirror icons flip.

## Button (D.7)

- The same set as ui-web «Button» (`docs/code/packages/ui-web.md`): `FoxButtonVariant` primary, secondary, danger, ghost; `icon`, `iconEnd`; `FoxButton.icon` is the circle with a required `label`; `loading`; `onPressed: null` is disabled (the Flutter convention, no separate flag). Comfortable only, 50 high: compact 40 is the panel's, a web app.
- Built on `FocusableActionDetector` (Enter, numpad Enter and Space activate), its own `MouseRegion` for hover (the detector's hover highlight is off in touch mode, so a mouse on Windows never showed it) and a `GestureDetector` for pressed and taps. A state-owned `FocusNode` and explicit `Semantics` (`button`, `enabled`, `focusable`, `focused`, `onTap`, `onFocus`) give the focus semantics; the detector's own are off.
- Only the colours animate (`AnimatedContainer` over `FoxDuration.base` and the theme's easing): the fill and the secondary border (`foregroundDecoration`, so the size never moves). The layout (minimum 48, 50 for the circle, inline padding, centring) is outside the animation; animating it made the button grow during the fade.
- The focus ring is a foreground `CustomPaint` (`_RingPainter`): a 2 stroke in `surface` around the button, then 2 in `button.focus-ring`, following its corners, the inside unpainted. It was two `BoxShadow`s first, but Flutter paints a shadow under the whole shape, so a focused ghost filled with `surface` on any other background (the review of D.7). The 2 and 2 are constants in `fox_button.dart`, not tokens: the web takes them from Tailwind's `ring-2 ring-offset-2` defaults; a token pair would serve both if they ever change.
- Semantics: disabled is neither enabled nor focusable (a focus state, even false, would mark the node focusable, so both are null); loading is focusable but not enabled and has no tap action, as the web's `aria-disabled` while busy.
- Loading keeps the content at opacity 0 (width and name kept) under a 270° spinner arc that turns once a second and stands still under `disableAnimations`. A disabled or loading button paints neither hover nor pressed; ghost's rest is its hover colour at alpha 0, so the fade has no grey step.
- `buttonStates` and `buttonVariants` feed the widgetbook coverage test (R3).
- Tests: semantics and sizes, keyboard and taps, disabled not focusable, loading keeps width, name and focus and ignores presses, the start icon on the right in RTL, no overflow at text scale 1.3 and 2.0, and each variant's rest, hover, pressed and focus-ring tokens.

## Inputs and forms (D.8)

- Drawn in `packages/design-tokens/src/forms-sheet.ts` (approved 2026-11-23); `FoxInputTheme` (`theme.input`) is `t.FoxInput.light` or `.captainLight`, one getter per `InputTokens` field. Comfortable density only. Orange `primary` is the focus outline, checked controls, switch, stepper border and current code cell; the keyboard ring is the blue `input.focus-ring` as the Button's.
- **Material boundary.** `material_ui` 1.11.1 (the decoupled Material, pinned like `widgetbook`), `flutter_localizations` and `intl` 0.20.3 are in `core_ui` only; only `lib/src/internal/material_scope.dart` and the text-entry and picker wrappers import it, always with the prefix `m`. `MaterialScope` is the one place a Material `ThemeData` is built, wholly from tokens (colour scheme, text theme, `NoSplash`, selection colours, date and time picker themes) with a transparent `Material`, and the `Localizations`: `FoxMaterialLocalizations` extends `m.MaterialLocalizationAr`. A Navigator-less tree has no Overlay: focusing a text field, opening a menu or a picker needs one, as in an app (the tests and the widgetbook coverage test add it).
- **Strings (AP §4.7)** in `FoxMaterialLocalizations`: Syriac months (`syriacMonths`), week from Saturday (`firstDayOfWeekIndex` 6), `dd/mm/yyyy` parsed strictly (31/02 refused), 12-hour time with «ص» and «م», Western digits (`formatDecimal`, `formatHour`, `formatMinute`), `timeOfDayFormat` always 12-hour. Its delegate loads synchronously (a `SynchronousFuture`), or the first frame is empty.
- **Shared pieces** (`lib/src/internal`, `lib/src/field`, not exported): `Interaction` (hover, press, keyboard focus, semantics, as the Button but for any control; `GestureDetector` excludes its own semantics so there is one node), `FocusRing` (the Button's two strokes), `FieldBox` (the pill: 1 border, 2 on focus or invalid, a foreground decoration so nothing moves; no border when disabled), `Entry` (`m.TextField` with a collapsed decoration, `buildCounter` returning null, `MergeSemantics` with the field's name and description), `PickBox` (a button-like pill for select, date and time), `AnchoredMenu` (an `OverlayPortal` and `CompositedTransformFollower` under the field, as wide as it; arrows, Enter, Escape and a tap outside), `ChoiceRow`, `Spinner`.
- **FoxField** wraps every control: label and marker («(اختياري)», passed in) above, hint or error (icon 16) below, optional counter at the end. `namesControl: false` for controls whose own semantics already carry the name and description (select, date, time, and the entries, which merge them into the text field's node): the label and the error are a separate node otherwise, which a screen reader reads as two things. The error is the description (`hint`) of the control's node.
- **Text:** `FoxTextField`, `FoxTextArea` (3 to 6 lines, counter `n/max` in graphemes, digits forced LTR), `FoxSearchField` (orange lens; clear button in a 48 target with a passed-in name; spinner replaces it while loading). The caller passes `error: null` for valid; a field never validates.
- **Phone:** the same rules as the web's `phone.ts`, and `test/phone_number_test.dart` mirrors every case of `phone.test.ts` (change both together). `FoxPhoneCountry` (`+963`, 9 digits, starts 9; `+90`, 10 digits, starts 5), `foxParsePhone(selected, text)` (country, display, e164, refused), `foxPhoneE164`, `foxPhoneFromE164`, `foxPhoneDigits` (Arabic-Indic ٠-٩ and Persian ۰-۹ become 0-9, everything else goes). `09…`/`9…` and `05…`/`5…`; text with its own calling code (`+`, `00`, or a bare `963…`/`90…` plus a full national number) belongs to that country and must be complete for it, else it is refused; digits are never cut (more than the country has is refused, shown as typed). In the field: the box keeps digits, `+`, spaces and dashes in Western digits; typing one more character past the country's length is dropped (a bare calling code is therefore pasted, not typed: type `+963…` or `00963…`), a longer paste shows whole and gives null; a valid number with another country's code calls `onCountryChanged` (the chip changes), replaces the box value with the national digits and the caret at the end (so Backspace deletes the last digit) and gives `onChanged` the E.164 with the new code, which is how an app hears the switch. One pill, the whole `Entry` under `Directionality(ltr)` (chip left, digits), the label and error RTL; `onChanged` gets the E.164 or null (incomplete or refused; ask `foxParsePhone` to tell them apart); country names are passed in.
- **Code:** six 48 circles under `Directionality(ltr)` over one `m.TextField` with transparent text and cursor, `autofillHints: oneTimeCode`, digits only, Arabic-Indic (٠-٩) and Persian (۰-۹) mapped to 0-9 first by a formatter before the filter, so typing, paste and autofill read the same (paste works at once); when the code is already full, new digits (a paste, a keystroke, autofill) replace it rather than being dropped by the length limit (`_ReplaceFullCode`, as the web), so a wrong code is retyped without deleting it; the cell at `text.length` has the orange outline while focused; `done` fills them orange and closes the 8 gaps over `FoxDuration.moment` with the fill, ignoring `disableAnimations` (the success moment); `done` also disables the input.
- **Select** is a menu under the field (`FoxSelectOption<T>`); it stays a menu on phones too (owner, D.10). Type-ahead in the open menu: typed letters move focus to the first option whose label starts with them, case-insensitive; a pause over 1 s starts a new word; a word with no match retries with the last letter alone; Space and Ctrl/Meta/Alt chords are ignored. **Checkbox** (`bool?`, null is mixed, a tap on mixed checks; Space only), **radio** (generic, a group is the radios sharing `groupValue`; inside a `FoxRadioGroup` the arrows move between them as the web RadioGroup: Down and the end-of-reading arrow go next, Up and the start arrow go previous, in RTL too, wrapping round, skipping disabled radios, and the selection follows the focus. Radios register in the group's list and are ordered by screen position, so a row works as a column. Outside a group only tap and Space work. The group takes `label`, `hint` and `error` (drawn by `FoxField`, with `SemanticsRole.radioGroup` naming the group and the error, else the hint, as its description) and is one tab stop: after each frame the selected enabled radio, else the first enabled one, keeps its place in the Tab order and the others get `skipTraversal` (arrows still focus them)), **switch** (52×32, off at the start; unchecked has rest, hover and pressed tracks, the pressed one its own token; the thumb slide takes zero time under `disableAnimations`), **stepper** (`min`, `max`, delete at the minimum when `onDelete` is set; `Semantics` with `label` and the count as its value («الكمية 2») plus increase and decrease; the circle's hover is `stepperBackgroundHover`, its outline `focusWidth` (2) as the web, and the bridge keeps clear a ring of `borderWidth + focusWidth` around each circle, the web sheet's 19 around a 16 radius).
- **Pickers:** `FoxDateField` (`DateTime`, date only) and `FoxTimeField` (`FoxTimeOfDay`, core_ui's own type so no Material type reaches an app) call `m.showDatePicker` and `m.showTimePicker` (input mode) from a context inside `MaterialScope` (they assert the localizations there); the date shows `dd/mm/yyyy` forced LTR, the time `3:05 م` reading right to left (digits as their own run, «م» after them at the left; not `ltrValue`); the typed-in date hint is `dd/mm/yyyy` (`dateHelpText`); `narrowWeekdays` stays overridden (without it Material shows English initials, no `ar` date symbols being loaded) and the delegate supports `ar` only; selection colour is `surfaceRaisedPressed`; the route sits above the field, so `pickerHost` re-wraps it with the captured `FoxTheme`, direction and scope.
- Tests: `text_field_test`, `choice_test`, `pick_test`, `phone_number_test`: semantics, tokens of each state, keyboard, RTL and LTR, both themes at 1.0, 1.3 and 2.0 (`expectNoOverflow`), the pickers' strings. The harness (`forms_harness.dart`) gives a Navigator with a new key per pump (a Navigator keeps the route it first built).
- Goldens (`forms_golden_test.dart`, per theme): the fields (hover, focus, invalid, disabled, area, search, phone, code), the controls (hover, pressed, keyboard focus, checked, mixed, disabled), the open select with the pickers and the code (done, invalid) and 130% text. `sheet.dart` takes a `size`.

Every `FoxTextTheme` style has `fontFamilyFallback: ['packages/core_ui/Fox Lira']`: the ₺ that CoFo lacks, declared in `pubspec.yaml` from `assets/fonts/fox-lira` (SIL OFL, cut by `packages/design-tokens/scripts/lira-font.py`). `loadFoxFonts` loads it under that name too, so goldens draw the real ₺.

- **Tests:** `test/data_test.dart` (locked in the slice); `expectNoOverflow` now renders on an 800×1600 surface: the test font draws each glyph as a square, so a card of real copy at 200% outgrew the default 600 high surface, which a phone scrolls. ## Overlays and navigation (D.10)

From the approved sheet «Overlays and navigation — batch 4» (owner, 2026-11-24), on tokens 0.8.0 (`caution`, `cautionSubtle`, `scrim` in `FoxColorScheme`; `FoxSize.dialog`, `toast`, `bar`):

- **FoxDialog** and `showFoxDialog` (a `RawDialogRoute`: the scrim, Escape mapped to `DismissIntent` in the route, back and a scrim tap close it unless `dismissible` is false; a fade and a 0.96→1 scale over `duration.base`, a fade only under reduced motion; `placement: bottom` puts it in the captain's thumb zone). The safe action autofocuses (`FoxButton.autofocus`, new): the secondary when the primary is destructive, else the primary. The app pops in its action. **FoxConfirmDialog** (AP §7.4): the reason field autofocuses; confirm stays pressable, and a blank reason shows `reasonError` and refocuses the field instead of calling `onConfirm` (the sheet drew it disabled; a disabled button would not say why); the money effect is a slot (an amounts summary) and the notified names are bell chips on the info tint. Both share the internal `DialogPanel` (scrolls as a whole when the height is bounded).
- **FoxBottomSheet** and `showFoxBottomSheet` (a `PopupRoute`: slides over `duration.slow`, a fade under reduced motion; drag past a quarter or a fling closes it, a shorter drag springs back; Escape, back and the scrim close it). At most 90% of the screen, the content scrolls, bottom padding is the larger of the home indicator and the keyboard. `sCurve` paints the brand's tab on the start side (`_SCurvePainter`, mirrored in LTR) holding the title, on `surface`; the plain top is `surfaceRaised` with the handle, the title and a ×. Semantics: a route named by the title, with a dismiss action. D.8's select stays a menu (owner).
- **FoxToast** (dark blue, the tone in its icon: the tone's subtle step on the blue; an underlined action and a 48 ×) and **FoxToaster** (`FoxToaster.of(context).show(...)`): one at a time, `bottomInset` above the bottom navigation; announced with `SemanticsService.sendAnnouncement`, assertive for danger, inside a live region whose fade always keeps semantics; `foxToastDuration` (4 s, 6 s warning, 8 s with an action, danger until closed); hover or focus inside pauses, leaving restarts.
- **FoxBanner** (`FoxBannerTone`: danger solid, caution, warning, info and neutral tinted; icon override such as `offline`; the action is a flexible underlined text so 200% text wraps) and **FoxBannerStack** (the first two, then a counter pill «+N» from `moreLabel` that expands in place and folds with `lessLabel`).
- **FoxMenu** (`FoxMenuItem`, `.separator()`, `destructive`): opens on an `OverlayPortal` under the trigger, aligned to its start, above it when the rows do not fit below; focus starts on the first row; arrows, Home, End, type-ahead, Tab or Escape close; the focus before opening is restored on close. `initiallyOpen` is for the catalogue and goldens.
- **FoxTabs** (`FoxTab`, `FoxTabsStyle.underline|pill`): only the selected tab is in the Tab order (`skipTraversal` on the rest); ← is next in RTL, → in LTR; Home, End; selection follows focus; the semantics label is «label، countLabel», selected, in a mutually exclusive group; the row scrolls and `Scrollable.ensureVisible` centres the selection. No `SemanticsRole.tab`: its debug checks require a tab bar parent with only tab children.
- **FoxTopBar** (the round secondary back button, the title a header in `heading`, an end slot) and **FoxRestaurantBar** (RA §6.2: name, the app's status pill, the connection dot with `connectionLabel` beside it, the support button).
- **FoxBottomNavigation** (`FoxNavItem`): the Figma file's floating bar in all three apps (owner): an `accent` pill with 48 circles on `surface`, the selected circle `primary` with a 4 px `primaryPressed` edge, icons only; the semantics label carries the badge («طلباتي، 1 جديد»), selected, without the enabled flags (`Interaction.enabledState: false`, new, as `selected`). **FoxNavigationRail**: 88 wide on the start side with the end border, the selected icon in a `primarySubtle` pill and the names shown; arrows move focus.
- **FoxPullToRefresh** listens to the child's scroll notifications (overscroll for clamping lists, negative pixels for bouncing ones), suppresses the leading glow, and past 80 runs `onRefresh` once; a custom semantics action (`refreshLabel`) refreshes without the gesture. **FoxRefreshDrop**: the logo's drop (`parseSvgPath`) filled from the bottom to `progress`, pulsing (opacity) while refreshing, still under reduced motion (owner: option B).
- **Tests:** `overlays_test.dart` and `navigation_test.dart` (locked in the slice) on `overlays_harness.dart` (a `WidgetsApp`, so Escape, back and Tab behave as in an app). Goldens: `overlays_golden_test.dart` (overlays and navigation on phone and captain, the restaurant tablet, 130% text; the sheets drawn on the scrim).
- **Goldens and shadows:** `flutter_test` sets `debugDisableShadows`, so a golden draws a soft elevation (the dialog's `high`) as a solid band; on a device it is the soft shadow of the token.

## Goldens (D.7, R9)

- `test/golden/` holds one image per theme and variant with every state at once (a mouse hovering, a held touch, keyboard focus), the icon-only circles, 130% text and the icon sheet at three sizes and mirrored; `sheet.dart` pumps them RTL at device pixel ratio 2 with animations off.
- They run on Linux only, since font rasterising differs by platform: `scripts/golden-docker.mjs` builds `fox-drop-golden:<.fvmrc version>` (a digest-pinned Ubuntu with Flutter cloned at the `.fvmrc` tag, because no ready image of Flutter 3.47 exists), copies the files the host's git lists (so a worktree works) and `.fonts/` into the container, runs `flutter test --tags golden --run-skipped` with any extra arguments, and copies the goldens (to a new folder, then swapped in) and `failures/` back, owned by the host user. The `golden` CI job runs it on Dart changes and on changes to the fonts manifest or the font-fetch scripts, after fetching the fonts (`FONTS_DEPLOY_KEY`), and uploads the failures; `verify` requires it.
- `loadFoxFonts` (`lib/testing.dart`) walks up to `.fonts/cofo-sans-pro-arabic` and loads 400, 500 and 700; it throws when they are missing instead of skipping, so a golden never passes on a fallback font.

## Lints (D.7, R2, R5)

`packages/fox_lints` (its own `CLAUDE.md`) is an analyzer plugin declared in the root `analysis_options.yaml`. It checks `core_ui` and `apps/widgetbook` only (`enforcedPackages`); `core_ui` may import Material (`materialPackages`). The theme mapping passes since it builds colours from token values, not literals.

## Left out

Wiring into the apps and bundling CoFo there (each app's screen slice, which also adds the app to `enforcedPackages`); compact density in Flutter; dark mode; the fox scenes inside the empty state's drop; Cupertino localizations for the iOS text toolbar (apps provide them); a hosted widgetbook.
