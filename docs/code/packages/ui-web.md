## The RTL, accessibility and visual gate (D.6, R4, R5, R9, T11)

Playwright (`playwright.config.ts`, `e2e/`) runs over the built static Storybook (`dist/storybook`), served by `vite preview` on port 6007; a story opens alone through `iframe.html?id=<id>&globals=surface:<x>` (`e2e/stories.ts` lists the ids from `index.json`).

- **`functional` project** (`e2e/rtl.spec.ts`, `pnpm test:e2e`, any OS, in `pnpm verify`): the built Storybook serves its preview with the tokens and its index; axe (WCAG 2.0 to 2.2 A and AA tags) finds nothing on any story. The Button and Icon checks (mirroring, keys, focus ring, 130% text) and `forms.spec.ts`, `overlays.spec.ts` left with their components in D.R1.
- **Parts inside their scrolling container** (`rtl.spec.ts`, after PR 300): on every story, phone and captain, after the fonts load and finite animations end, each element whose `overflow-x` or `overflow-y` clips (`auto`, `scroll`, `hidden`) and overflows is checked. Every visible part (a box larger than 1 px, not `sr-only`; `aria-hidden` icons and badges count, since they are seen; not fixed; not inside a nested clipping container; not absolute with its `offsetParent` outside) lies within the scrollable area: the padding box moved by the scroll position, extended by `scrollWidth`/`scrollHeight`, to the left in RTL. An absolute part must also lie over the in-flow content or the visible box, since it widens the scroll range itself (the old Tabs indicator did, proved against `tabs.tsx` of `3286b321`). Looping animations are paused first. Then the scroll ranges are read again after two frames and 200 ms and must be unchanged, and every overflowing container is scrolled to its far end (negative `scrollLeft` in RTL) and checked once more. A failure reads `<part> at x..x × y..y outside [the content of] <container> x..x × y..y`.
- **axe without `color-contrast`:** the token contrast test (`design-tokens/src/contrast.ts`) is the contrast gate and knows the owner's accepted brand-orange pairs; axe cannot.
- **`visual` project** (`e2e/visual.spec.ts`): `toHaveScreenshot` of every story on the phone and captain surfaces, animations frozen, full page. It exists only when `FD_VISUAL=1`, because baselines (`e2e/__screenshots__/`, no platform suffix) are valid only from `mcr.microsoft.com/playwright:v1.64.1-noble` (keep it equal to the `@playwright/test` pin). It fails, never skips, when CoFo is missing from the build or does not load: run `pnpm fonts:fetch` and rebuild. A test fails when a baseline belongs to no story; with no story it has no screenshots.
- **Docker locally:** `scripts/visual-docker.mjs` runs the image with the repo mounted, `node_modules` in named volumes (`fd-visual-*`, so the host's Windows install is untouched), the `packageManager` pnpm installed once into its own volume, `pnpm install --frozen-lockfile --filter "@fox-drop/ui-web..."` only when the lock file, the workspace or the installed manifests changed since the volume's last install (a marker in `node_modules`; the install costs about 2 minutes, pnpm checks the lock file against the registry), then the visual project. Arguments pass to Playwright; `FD_VISUAL_STORIES` (a comma list of story ids) and `FD_VISUAL_REPORT` (a JSON report) pass into the container. The Storybook is built on the host first.
- **`pnpm baselines`** (`scripts/baselines.mjs`, root) is the one command for these screenshots and the core_ui goldens: it builds the Storybook (Turborepo's cache), picks the stories the change since `origin/main` reaches (a changed module selects the stories whose file imports it, directly or not; the theme, the tokens, Storybook's or Playwright's set-up and the lock file select all), updates, compares again, lists the images that changed, removes baselines of no story, and records the checked tree in the git folder; `--status` (under a second, no Docker) says whether this tree's images are checked, and `verify --changed` shows it in its table. Since D.R1 it tolerates a missing `__screenshots__` folder.
- **CI:** the `visual` job runs in the same image, fetches the fonts (a missing `FONTS_DEPLOY_KEY` fails it), builds and runs the project, and uploads `test-results` (expected, actual, diff) on failure. The `verify` job requires it.

## Package skeleton (D.6, step 3)

- **Package:** `@fox-drop/ui-web`, private, ESM; `exports` point at TypeScript source (`./src/index.ts`) and `./styles.css`. Exact pins as in D.6 (archive `docs/slice-notes.md`) (`@ui-sdk/react` and `@ui-sdk/core` 0.1.0-beta.14 both exist on npm, Storybook 10.6.8, Tailwind 4.3.5).
- **Styles:** `src/styles.css` imports Tailwind, `tokens.css` and `tailwind.css` of `design-tokens`, and declares CoFo 400, 500 and 700 from `/fonts/cofo-sans-pro-arabic/CoFoSansProArabic-{Regular,Medium,Bold}.ttf`, the files and names of `scripts/font-metrics.mjs` (`WEIGHTS`). Storybook serves the repository's `.fonts/` at `/fonts` when the folder exists; without it (a fork's pull request) the build passes and text uses the fallback. It also declares «Fox Lira» (the ₺, `unicode-range: U+20BA`, from the committed `fonts/fox-lira/`, SIL OFL), the `font.family.sans` fallback, and imports `src/theme.css`, the theme extensions shared with `scripts/bundle.css` (since D.R1 only the photo ratios `aspect-cover` 16:9 and `aspect-dish` 1:1 of brand expression §5, which the token theme's reset of `aspect-video` requires).
- **Storybook:** `.storybook/main.ts` (react-vite, `@tailwindcss/vite`, telemetry off), `preview.tsx` (decorator `dir="rtl" lang="ar"`, toolbar global `surface`: phone default, captain sets `data-surface="captain"` as `tokens.css` defines it, panel uses the default tokens).
- **Lint (R1, R3, R5, T11):** `eslint.web.mjs` holds a local plugin rule `fd/design` over every string and template literal and the `style` prop: arbitrary Tailwind value, hex colour, physical direction. `webAppConfig` (apps) bans `@ui-sdk/*` and `@base-ui/*`; `uiWebConfig` bans only `@ui-sdk/react/agent`. Stories and `*.test.tsx` skip the JSX-text rule. Known limits: any `-[` in a string counts as arbitrary (so `data-[state=open]:` fails too); a hex-looking anchor such as `#add` would count as a colour.
- **Wiring:** Turborepo picks `lint`, `typecheck`, `test` and `build` up from the scripts. In `classify-changes.mjs` a path under `packages/ui-web/` is not Dart, so it counts as TypeScript (`code`, `typescript`); since PR 285 it also sets `visual`, the CI job that runs the screenshots (with `design-tokens`, the root manifests and the fonts' scripts).
- **Apps (skeleton):** no `style=` or physical class. The lint found four hex literals in `apps/admin` (a white canvas fill in `banners-page.tsx`, the QR's white and black in `setup-page.tsx`); they became `white` and `black`, which stay fixed because a QR code needs that contrast in any theme.

## Design System bundle (D.6, §9.8)

- **Command:** `pnpm --filter @fox-drop/ui-web design-system` (`scripts/design-system.ts`) adds `bundle.js`, `bundle.css`, `index.d.ts` and a `<Name>/` folder (`README.md`, `preview.html`) per entry of `COMPONENTS` (`scripts/bundle.ts`, empty since D.R1; an approved component joins it with its entry in `bundle-entry.ts` and its types in `docs.ts`) under `packages/design-tokens/.design-system/system/project/components/`. It must run after the design-tokens `design-system`, which empties `.design-system/system` on its first run.
- **bundle.js:** one classic IIFE from Vite library mode (`scripts/bundle.ts`, entry `scripts/bundle-entry.ts`), minified, `NODE_ENV` production, line 1 the `@ds-bundle` header (format 4, namespace `FoxDrop`, the `COMPONENTS`). React 19 and `react-dom/client` are inside because the index lists `libraries: []`; `window.FoxDrop` holds the components, `React` and `ReactDOM`, and `window.React` and `window.ReactDOM` are set only when absent. `</script` and `<!--` are escaped (`<\/script`, `<\!--`) and the build fails if any is left or the file passes 6 MB.
- **The React 18 bridge (D.11, 2026-11-24):** a Design canvas renders `component-from-global-scope` components with its own React 18 (`window.React`), and React 19 elements inside a React 18 tree fail with React error #31, so every screen of the first screens canvas broke. Each `FoxDrop` export is now a bridge: under the bundle's own React it renders the real component directly (the Design System's previews); under another `window.React` it renders an empty `display: contents` element with the page's hooks and mounts the real component there with the bundle's `createRoot`, converting the page's elements in its props and children (tags, fragments and other bridged components, static parts included) into the bundle's, inside arrays and plain objects and in what function props return (a table's cells). Which React renders is told by trying one of the bundle's hooks, which only works while the bundle's React renders, so a card that renders through `FoxDrop.React` beside a page React 18 goes straight through (review of D.11). A component of the page alone cannot cross and renders nothing. The UI SDK needs React 19, so building against the page's React was not an option. The build sets `mode: 'production'` and `oxc.jsx.development: false`, since under Vitest the transform emitted `jsxDEV` calls that the bundled production React lacks. Its test (React 18's UMD builds, dev dependencies `react-18`, `react-dom-18`, rendering a component through the bridge) left with the components in D.R1 and comes back with the first one.
- **bundle.css:** `scripts/bundle.css`: Tailwind scanned over every `src/**/*.ts` and `*.tsx` module but stories and tests, `src/theme.css`, the `--fd-*` variables of `tokens.css` and the theme of `tailwind.css`. No `@font-face` and no `.fonts` url (the system serves CoFo from `tokens.json`); the build fails on `</style`, `@font-face` or more than 2 MB.
- **Docs files:** `index.d.ts` is generated (icon names inlined, no imports) and its props mirror each component's by hand (`docs.ts`); READMEs and previews live in `packages/ui-web/design-system/<Name>/` (none since D.R1). A preview is a card (`@dsCard`, a group) that renders every state with `FoxDrop.React` in an RTL root; the frame preloads the tokens, CSS and script.
- **Tests:** `test/design-system.test.ts` builds the bundle (a few seconds), runs it in jsdom and checks the rules above with zero components.

## Lessons for forms and popups (D.8, D.10)

Their code left in D.R1; these apply again when an approved screen brings such a component back (moved here from `packages/ui-web/CLAUDE.md` on 2026-11-27).

- **Forms (D.8):** the theme has named spacing only (`gap-2xs`, `w-2xl`; `min-w-0` makes no CSS, use `min-w-none`). A string or template in a JSX `{}` is text: build it above the `return`. Stack states as `group-hover/row:data-checked:`; the SDK sets `data-checked`, `data-unchecked`, `data-indeterminate`, `data-open`.
- **Shared classes** go in a `.ts` module the bundle sources. Fields use `@ui-sdk` Field, so give a second control inside one (the phone chip) its own `<Field>`.
- **Popups (D.10):** none starts open (a story opens it with `play`); a trigger is the project's button component through the SDK's `render`; the side drawer is the SDK's Dialog (its Drawer is physical).

## The components canvas (D.C1)

`scripts/components-canvas/` writes the Design canvas "Fox Drop Components" from the code into the ignored `.components-canvas/project/` (`pnpm --filter @fox-drop/ui-web components-canvas --config <file> --current <canvas.json>`), after the Shifa project's canvas (its ADR-0048) with its weak points fixed. One board per component, nothing hand-written per component. Since D.R1 it runs with zero components: the index says no component is approved yet (`test/components-canvas.test.ts`). **Open for the first board:** `playground.ts`'s panel mounts `FoxDrop.Switch`, `Select`, `TextField` and `Button` (the controls, Reset and the scenario buttons), none of which exists now, so the first board needs those components back or the panel redrawn without them.

- **Data from the stories:** `stories.ts` loads each `<name>.stories.tsx` and `<name>.tsx` through Vite's SSR module loader (`storybook/test` aliased to a stub; a `play` is noticed, never run) and maps `STATES` × `VARIANTS` to stories as `test/stories.test.ts` does. Args cross as JSON: an element becomes `{ $el: 'Button' | 'p', props }` (a story-local component is an error naming the story), a function `{ $fn }`, a `Set` or `Date` marked; `page.ts`'s `hydrate` rebuilds them in the board's logic class with `window.React.createElement(FoxDrop.X, …)`, which the bundle's React 18 bridge converts.
- **The board (`board.ts`):** the header (Arabic description, when to use and not, `FoxDrop.<Name>`, the token files it reads and their web and Flutter readers), the playground (`playground.ts`: controls from the props types of `docs.ts`, string-literal unions as a Select, booleans as a Switch, text and numbers as a TextField, all FoxDrop components; Tweaks hold the starting values; scenarios are the stories outside the matrix; `key` remounts the copy on a new story), the surfaces side by side (phone, captain `data-surface="captain"`, the panel compact where the component has `density`), the state matrix (variants by states, or a grid of states; hover, pressed and keyboard focus in a `data-pseudo-outer` frame; a story with `play` drawn with `open` and `inline` where the component has `inline`), and the anatomy (`anatomy.ts`: the component token files whose web readers include the folder, only the tokens its sources and the src modules they import read, since one token file may serve several components; parts by state suffix; light values from `tokens.css`).
- **Arabic copy in one file:** `copy-ar.ts` (owner-approved exception to English-only storage): group names, headings, each component's description, and `WORDS`, from which a state or story name (`PrimaryHover`, `readOnly`) gets its caption; a missing word throws.
- **Forced states per board:** `states.ts` (Shifa's, postcss over `bundle.css`) copies each `:hover`, `:active`, `:focus(-visible)` rule under a `data-pseudo` frame, keeps only the `outer` frame the boards use and, after a measuring pass, only the rules whose classes the check saw on that board: 5 to 13 KB a board (all frames and rules: 962 KB).
- **The check (`check.ts`, `render-board.ts`):** Chromium with React 18 UMD on the page (as the canvas), the bundle, the board's sheet and CoFo from `.fonts/` (the main checkout's from a worktree); each board at its Tweaks, its props changed and every scenario; reports page and console errors and warnings, unresolved holes, a missing component, content wider than its panel (unless a scrolling box clips it) and content taller than its board. `--measure` writes `heights.json` and `classes.json` beside `project/`; `--shots <dir>` a picture per board. So: write, measure, write, check.
- **Play in the check (audit, 2026-11-27):** after the combinations, `check.ts` renders each board once more with `live: true` (`render-board.ts`: `setState` merges the state and draws the board again, as the canvas does) and `play.ts` plays it with Playwright's real pointer and keys: Tab reaches every control of the copy in the tab order; the arrow keys (either way) move within a tab list, radio group or menu; every enabled control of the copy (a soft-disabled one too, `aria-disabled` without busy) takes a press (a checkbox, switch or radio then changes, a field takes typing), a trigger with `aria-expanded` opens and Escape closes it; then every switch, choice and text of the panel, Reset and each scenario button redraw the copy. A finding names the element and what did not happen. `PLAY_DEBUG=1` prints each press. The check's server serves files only, a pressed link stays on the board, a failed load is reported with its address, Play types no text into a photo's or link's address and steps a spin field with ArrowUp. A popup drawn in place with no trigger of its own gets an `open` switch in the panel when its stories' meta says `parameters: { canvas: { openSwitch: true } }` (`playground.ts`), as an app opens it from outside; Play switches it off and on again.
- **How a board draws them:** a component whose docs type has `inline` gets `inline: true` on every copy, the playground included, so what Play opens stays in its cell; a story with `play` is drawn `open` unless its `parameters.canvas` says `open: false` (it types, nothing opens); `gesture: true` captions it «بالإيماءة في Play، مرسومة هنا قبلها». A story whose `render` mounts a wrapper of its own with the meta component's props and no args is drawn as the meta component with those props. A function prop called with several arguments crosses as a table too (`CALLS`, a sample of several arguments is a `Spread`, keyed on the canvas by the list of arguments); a `{ $fn }` that should give content would hand React a Promise and blank every copy, which the check does not catch (no error is logged). `check.ts` read the first board name as `--shots`' folder when `--shots` was absent (fixed).
- **Every board (D.C2):** `BOARDS` is `COMPONENTS`. A story's `render` (its own or its meta's) runs in Node and the first library component it draws gives the props; a child from outside the library crosses as its static markup drawn inside that component (`{ $html }`, `react-dom/server`; a label is not tied to it on the canvas); a `render` whose wrapper gets the args as they are keeps them. A function prop that gives content is called in Node over the inputs the story gives it and crosses as a table (`{ $memo }`, `CALLS` in `stories.ts`); any other function becomes a 1.5 s wait, so a press shows its pending state. A state only a gesture reaches (`play` on a component without `inline`) is drawn at rest, its caption says so, and it is no scenario. A component with static parts mounts them as `FoxDrop.<Name>.<Part>`. `Main.dc.html` (`index.ts`; `Index.dc.html` until D.C4 retired the old Main) leads the page with a link to every board by group; each group has a `title1` note with its count; four boards a row. `WIDE` boards put their surfaces and states one a row.
- **Script-safe JSON:** values embedded in a board's `<script>` go through `js()` (`page.ts`), which escapes `<`, so a story string can never close the script.
- **Publishing:** the board files, `support/states/`, `canvas.json` (title, the pages `components` «المكوّنات المعتمدة» and `proposals` «المكوّنات المقترحة»), with `ds/fox-drop/tokens.json` and `components/bundle.{js,css}` copied server side from the Design System (its bundle.css carries the `--fd-*` variables; it has no tokens.css). The config, outside the repository, holds the system's link and version and the CoFo blob urls.
- **The proposals page and T15 (D.C4):** the board is the drawing the owner approves (decision T15). «المكوّنات المقترحة» holds a sticky note on a proposal's life cycle (`PROPOSALS_NOTE` in `copy-ar.ts`, note `proposals-life-cycle`) and any component drawn there before it is coded; such a board stays until the generator writes a board of the same file name, which replaces it. `RETIRED` names the six hand-drawn boards of the old "Component proposals" canvas (`Main`, `Buttons`, `States`, `Forms`, `Data`, `Overlays`, approved in D.6 to D.10): the index drops them, and their files leave the canvas by `"project/<file>": null` in the publish (`Main.dc.html` is overwritten by the index, so `Index.dc.html` goes the same way).
