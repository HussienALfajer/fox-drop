# packages/ui-web

## Icon (D.6)

- `src/icon/icon.tsx`: `<Icon name size="sm|md|lg" label?>` over `@fox-drop/design-tokens/icons`. Inline SVG, viewBox 24, `stroke="currentColor"`, width 2, round caps and joins, no fill; the size classes read `size.icon-*` as `size-(--fd-size-icon-md)`; a `mirror` icon gets `rtl:-scale-x-100`; no `label` means `aria-hidden="true"`, with it `role="img"` and `aria-label`. Exports `Icon`, `IconName`, `IconProps` and `STATES` (default, sm, md, lg, labelled, mirrored).
- **Set v4 Madar (D.5b):** stroke 1.5 and the prop `variant` (`ICON_STYLES`: linear by default, duotone, brand-duo, broken, bold, bold-duo). It is `variant`, not the slice plan's `style`, because the web lint refuses any JSX attribute named `style` (R1). Duotone sets `opacity` 0.5 on the non-accent paths, Brand Duo strokes the accent in `var(--fd-color-brand)`, Broken draws `broken`, Bold and Bold Duo fill the baked layers in `currentColor` (`stroke="none"`, `fill-opacity` 0.5 on faded ones): no mask, no dash. `STATES` gains duotone, brandDuo, broken, bold, boldDuo (camel case, the stories' names). `EmptyState` draws Brand Duo; the sidebar stays Linear.
- Stories: one per state, named by it (`Default`, `Sm`, `Mirrored` shows `back`). Tests: the paths, the hidden or named role, the size classes, the mirror class only on `back`, `motorcycle`, `car`.

## Button (D.6)

- **The look:** the approved sheet (`button()` in `design-tokens/src/button-sheet.ts`), read from `(--fd-button-*)` tokens: variants primary, secondary (1px inset border, no `border` so the size stays), danger, ghost; comfortable 50 and compact 40; icon-only circle. No shadow. Focus: `ring-2` in `button.focus-ring` with `ring-offset-2` in `surface`, `focus-visible` only.
- **Hover and pressed (R10, owner 2026-11-24, «Brand tonal steps»):** `hover:` and `active:` paint each variant's own `button.<variant>.background-hover` and `-pressed` tokens, and the secondary outline turns `border-hover` blue; the colour fades over `duration.base` (`transition-colors`), nothing moves. design-tokens' `STATE_TRIPLES` test measures them visible (ΔE2000); the RTL gate checks each variant paints them. History: a 12% then 50% `before:` overlay mixing fill and pressed measured ΔE 3.3 (primary) and 1.3 (ghost) and was not seen, so the owner asked for one state model for every component. A disabled or loading button has neither state.
- **On the UI SDK:** `@ui-sdk/react/button` (`Button`, a native `<button>`; options `disabled`, `focusableWhenDisabled`, `type`, `pendingAnnouncement`; `onClick(event, details)`). Its `disabled` stops presses and keyboard activation (Enter and Space work natively). `loading` passes `disabled` with `focusableWhenDisabled`, so the button keeps focus (`aria-disabled`) and ignores presses, and sets `aria-busy`. The SDK's own pending (an `onClick` returning a Promise, announcing English «Loading») is not used.
- **Props:** `variant`, `density`, `icon`, `iconEnd`, `loading`, `disabled`, `type`, `onClick`; `children` or, for an icon alone, a required `label` (a union type). Icons are 24 when comfortable and 16 (`size.icon-sm`) when compact. Loading keeps the label in the layout with `invisible` and centres a spinner over it, so the width does not move. The label uses `text-phone-subtitle` (18, 1.3, 500) or `text-panel-subtitle` (16) when compact.
- **Exports:** `Button`, `ButtonProps`, `ButtonVariant`; `STATES` (default, hover, focus, pressed, disabled, loading, comfortable, compact) and `VARIANTS` stay in `src/button/button.tsx`.
- **Stories:** `<Variant><State>` for every pair (`PrimaryHover`, `GhostCompact`) plus `WithIcon*`, `CompactWithIcon` and `IconOnly*`. Hover, focus and pressed are plain interactive stories; the RTL gate drives them. The component has no state prop.

`test/setup.ts` loads jest-dom and cleans up after each test. `test/stories.test.ts` takes every capitalised function exported by `src/index.ts`, maps `FooBar` to `src/foo-bar/foo-bar.stories.tsx`, imports `STATES` (and `VARIANTS`) from `src/foo-bar/foo-bar.tsx` and requires a story export ending in each state's PascalCase name, or exactly `<Variant><State>` when `VARIANTS` exists. `STATES` is not exported from `src/index.ts` (two components would collide).

## The RTL, accessibility and visual gate (D.6, R4, R5, R9, T11)

Playwright (`playwright.config.ts`, `e2e/`) runs over the built static Storybook (`dist/storybook`), served by `vite preview` on port 6007; a story opens alone through `iframe.html?id=<id>&globals=surface:<x>` (`e2e/stories.ts` lists the ids from `index.json`).

- **`functional` project** (`e2e/rtl.spec.ts`, `pnpm test:e2e`, any OS, in `pnpm verify`): the start icon of a Button sits right of its label and `iconEnd` left of it; `back` is mirrored (`scale` is negative: Tailwind 4 flips with the `scale` property) and a plain icon is not; Enter and Space activate a focused button (the `Presseable*` stories count `onClick`), a disabled button is skipped by Tab, and a loading one ignores both keys and the pointer; a keyboard-focused button has a box-shadow ring that an unfocused one lacks; axe (WCAG 2.0 to 2.2 A and AA tags) finds nothing on any story; at 130% text (the root font size, since every length is rem) no Button label clips and its content stays inside the button.
- **Parts inside their scrolling container** (`rtl.spec.ts`, after PR 300): on every story, phone and captain, after the fonts load and finite animations end, each element whose `overflow-x` or `overflow-y` clips (`auto`, `scroll`, `hidden`) and overflows is checked. Every visible part (a box larger than 1 px, not `sr-only`; `aria-hidden` icons and badges count, since they are seen; not fixed; not inside a nested clipping container; not absolute with its `offsetParent` outside) lies within the scrollable area: the padding box moved by the scroll position, extended by `scrollWidth`/`scrollHeight`, to the left in RTL. An absolute part must also lie over the in-flow content or the visible box, since it widens the scroll range itself: the old Tabs indicator, placed from the list's physical edges, sat beyond every tab and stretched the range to hold itself, so the first rule alone passed it (proved against `tabs.tsx` of `3286b321`). Looping animations are paused first. Then the scroll ranges are read again after two frames and 200 ms and must be unchanged, and every overflowing container is scrolled to its far end (negative `scrollLeft` in RTL) and checked once more. A failure reads `<part> at x..x × y..y outside [the content of] <container> x..x × y..y`.
- **axe without `color-contrast`:** the token contrast test (`design-tokens/src/contrast.ts`) is the contrast gate and knows the owner's accepted brand-orange pairs; axe cannot.
- **`visual` project** (`e2e/visual.spec.ts`): `toHaveScreenshot` of every story on the phone and captain surfaces, animations frozen, full page. It exists only when `FD_VISUAL=1`, because baselines (`e2e/__screenshots__/`, no platform suffix) are valid only from `mcr.microsoft.com/playwright:v1.64.1-noble` (keep it equal to the `@playwright/test` pin). It fails, never skips, when CoFo is missing from the build or does not load: run `pnpm fonts:fetch` and rebuild.
- **Docker locally:** `scripts/visual-docker.mjs` runs the image with the repo mounted, `node_modules` in named volumes (`fd-visual-*`, so the host's Windows install is untouched), the `packageManager` pnpm installed once into its own volume, `pnpm install --frozen-lockfile --filter "@fox-drop/ui-web..."` only when the lock file, the workspace or the installed manifests changed since the volume's last install (a marker in `node_modules`; the install costs about 2 minutes, pnpm checks the lock file against the registry), then the visual project. Arguments pass to Playwright; `FD_VISUAL_STORIES` (a comma list of story ids) and `FD_VISUAL_REPORT` (a JSON report) pass into the container. The Storybook is built on the host first.
- **`pnpm baselines`** (`scripts/baselines.mjs`, root) is the one command for these screenshots and the core_ui goldens: it builds the Storybook (Turborepo's cache), picks the stories the change since `origin/main` reaches (a changed module selects the stories whose file imports it, directly or not; the theme, the tokens, Storybook's or Playwright's set-up and the lock file select all), updates, compares again, lists the images that changed, removes baselines of no story, and records the checked tree in the git folder; `--status` (under a second, no Docker) says whether this tree's images are checked, and `verify --changed` shows it in its table.
- **CI:** the `visual` job runs in the same image, fetches the fonts (a missing `FONTS_DEPLOY_KEY` fails it), builds and runs the project, and uploads `test-results` (expected, actual, diff) on failure. The `verify` job requires it.
- **Found by the gate:** a loading Button hid its label with `invisible` (visibility hidden), which removed its accessible name; it now uses `opacity-0`.

## Design System bundle (D.6, §9.8)

- **Command:** `pnpm --filter @fox-drop/ui-web design-system` (`scripts/design-system.ts`) adds `bundle.js`, `bundle.css`, `index.d.ts` and `Button/`, `Icon/` (`README.md`, `preview.html`) under `packages/design-tokens/.design-system/system/project/components/`. It must run after the design-tokens `design-system`, which empties `.design-system/system` on its first run.
- **bundle.js:** one classic IIFE from Vite library mode (`scripts/bundle.ts`, entry `scripts/bundle-entry.ts`), minified, `NODE_ENV` production, line 1 the `@ds-bundle` header (format 4, namespace `FoxDrop`, Button and Icon). React 19 and `react-dom/client` are inside because the index lists `libraries: []`; `window.FoxDrop = { Button, Icon, React, ReactDOM }`, and `window.React` and `window.ReactDOM` are set only when absent. `</script` and `<!--` are escaped (`<\/script`, `<\!--`) and the build fails if any is left or the file passes 6 MB.
- **The React 18 bridge (D.11, 2026-11-24):** a Design canvas renders `component-from-global-scope` components with its own React 18 (`window.React`), and React 19 elements inside a React 18 tree fail with React error #31, so every screen of the first screens canvas broke. Each `FoxDrop` export is now a bridge: under the bundle's own React it renders the real component directly (the Design System's previews); under another `window.React` it renders an empty `display: contents` element with the page's hooks and mounts the real component there with the bundle's `createRoot`, converting the page's elements in its props and children (tags, fragments and other bridged components, parts such as `Skeleton.Block` included) into the bundle's, inside arrays and plain objects (`Tabs`' content) and in what function props return (`DataTable`'s cells). Which React renders is told by trying one of the bundle's hooks, which only works while the bundle's React renders, so a card that renders through `FoxDrop.React` beside a page React 18 goes straight through (review of D.11). A component of the page alone cannot cross and renders nothing. The UI SDK needs React 19, so building against the page's React was not an option. The build sets `mode: 'production'` and `oxc.jsx.development: false`, since under Vitest the transform emitted `jsxDEV` calls that the bundled production React lacks. `test/design-system.test.ts` loads React 18's UMD builds (dev dependencies `react-18`, `react-dom-18`) and renders a Button and a Skeleton through the bridge.
- **bundle.css:** `scripts/bundle.css`: Tailwind scanned only over `src/**/*.tsx` (not stories or tests), the `--fd-*` variables of `tokens.css` and the theme of `tailwind.css`. No `@font-face` and no `.fonts` url (the system serves CoFo from `tokens.json`); the build fails on `</style`, `@font-face` or more than 2 MB.
- **Docs files:** `index.d.ts` is generated (icon names inlined, no imports) and its props mirror `button.tsx` and `icon.tsx` by hand; READMEs and previews live in `packages/ui-web/design-system/<Name>/`. A preview is a card (`@dsCard`, group Actions or Icons) that renders every state with `FoxDrop.React` in an RTL root; the Icon preview takes its names from the package. The frame preloads the tokens, CSS and script.
- **Tests:** `test/design-system.test.ts` builds the bundle (a few seconds), runs it in jsdom and checks the rules above.
- **Verified by hand:** both previews were rendered in headless Chromium over `generated/tokens.css`, `bundle.css` and `bundle.js` with no console error.

## Forms: Field, TextField, TextArea, SearchField (D.8)

- **The look:** the approved sheet (`forms-sheet.ts` in design-tokens), read from `(--fd-input-*)` tokens through the shared `box` in `src/field/styles.ts` (`formTv` also declares the `text-<surface>-<role>` sizes tailwind-merge would take for colours). The outline is an inset ring: 1 `border-strong` at rest, `border-hover` on hover (`not-focus-within:hover:`), 2 `primary` on `focus-within`, 2 `danger` when invalid (it stays red when focused), `disabled` fill and `on-disabled` text. Pills are 50 high (`min-h-(--fd-input-height)`), compact 40; `TextArea` uses the radius `input.area-radius`.
- **Field:** `<Field label optionalLabel hint error aside disabled name density>` on the UI SDK's `Field`, `FieldLabel`, `FieldDescription` and `FieldError match` (the SDK wires `for`, `id`, `aria-describedby`, `aria-invalid`). The error replaces the hint and carries the `error` icon at 16; `optionalLabel` is the passed text («(اختياري)»), never a star. `aside` is the end of the line below (the counter).

- **Exports and stories:** each exports `STATES` (`default, hover, focus, filled, invalid, disabled` plus `comfortable, compact`, `counter` or `loading` as it fits) with one story per state; hover and focus are plain stories the gates drive.

## Forms: PhoneField and CodeField (D.8)

- **PhoneField:** one pill (`InputBox dir="ltr"`) holding the country chip (a `Select` trigger with the `chevron-down` icon that turns when open) and the digits `Input` (`type="tel"`, `autocomplete="tel-national"`); the label and the error stay RTL. The chip sits in its own SDK `Field` (`className="contents"`) so it is a separate control named by `countryLabel`, not by the number's label. Its menu opens with `dir="rtl"` over «سوريا +963» and «تركيا +90» (`countryLabels` are props).
- **The rules (`src/phone-field/phone.ts`, tested first, CU §5.2):** Syria 9 digits starting with 9, Turkey 10 starting with 5; a leading `0` is dropped; digits are never cut (as Flutter's `foxPhoneE164`): typing stops at the country's length and a pasted number that is too long is shown as it came with `''` reported. `parsePhone(selected, text)` reads a number with its own calling code (`+90…`, `0090…`, or exactly the code and a full national number such as `963912345678`) as that country's, whichever is picked, and the chip switches (`onCountryChange`); a calling code with a wrong rest is refused, never reshaped. Arabic-Indic and Persian digits become Western (AP §4.7). `onValueChange(e164, {country})` gets `+963912345678` once the number is complete and `''` before; `value` (E.164), `defaultValue`, `country`, `defaultCountry` and `onCountryChange` cover control. A controlled `value` that the typed digits do not make replaces them.
- **CodeField:** the SDK's `OTPInput` (`maxLength` 6, `pattern="digits"`, `autocomplete="one-time-code"`, `inputMode="numeric"`), `dir="ltr"`, six `OTPInputSlot` circles of `input.code.size` with the current one ringed in `primary` and a `pulse` caret (still under `motion-reduce`). `onValueCommit` is `onComplete`; `done` fills the cells with `input.code.color.done` and takes the gap to 0 over `duration.moment` (not switched off under reduced motion, owner 2026-11-23); `error` rings them red, except the current cell, which keeps the orange outline so the user sees where the next digit goes. The SDK keeps only 0-9, so Arabic-Indic and Persian digits typed or pasted are turned into Western digits before it sees them (a `beforeinput` and a paste handler on a wrapper; the value is then held by the component).

## Data display (D.9)

Drawn on «Data display — batch 3» (`packages/design-tokens/src/data-sheet.ts`), approved by the owner on 2026-11-24 with every proposal. Eleven components, each with its story per state and a Design System card (group Data):

- **Money:** `formatAmount(minor, decimals, {signed})` builds the text from the digit string, never a float: a Western comma between thousands, a whole amount drops its fraction, any other shows every minor digit, U+2212 for minus, `+` only when `signed`. `Money` renders it plus a space and the symbol in one `<bdi dir="rtl">`, tabular, so in Arabic the symbol sits to the amount's left (the Figma file's «TL 450»), and the minus reads first (at the right). The symbol and decimals come from the app (currencies are data rows, AP §8.6). The ₺ is drawn by «Fox Lira», the `font.family.sans` fallback, from `fonts/fox-lira/` (committed, SIL OFL; `styles.css` declares it with `unicode-range: U+20BA`; Storybook serves it at `/fonts/fox-lira`; an app copies it next to its bundle as it does CoFo).
- **StatusChip:** `STATUS_LOOK` gives each AP §8.1 state its tone and icon; or a free `tone` and `icon` (a restaurant's «مشغول»). The label is always the app's own words. Tone text on its `*-subtle` tint; the primary tone's text is `on-primary-subtle`.
- **CountBadge:** `badgeText` caps at `max` («99+»); the digits run LTR and are hidden, `label` (sr-only) gives the full count; no count is a dot; zero renders nothing; a ring of `surface-raised` parts it from the icon.
- **Card:** `elevation` `offset` (the customer app) or `outline` (everywhere else); `tone="danger"` for a late order; with `onPress` the whole card is one `<button>` with the R10 raised-surface states.
- **ListRow:** a `<div>` or, with `onPress`, one `<button>` named by the title and described by the second line. The chevron is `back` (which mirrors under RTL) inside a span flipped once more, so it points along the reading direction. A danger row has no chevron.
- **Timer:** `formatDuration` («4:32» under ten minutes, «12 د» from ten, whole seconds, never negative) and `timerTone` (soon in a countdown's last minute, late when the app says); `role="timer"`, which screen readers do not announce per tick.
- **OrderCard:** RA §8.2's compact card as an `<article>` named by `label`, plus `lateLabel` when late; the one main button is optional (the portal is read-only, RA R15).
- **AmountsSummary:** the lines as a `<ul>` with dashed rules, a line's `text` replaces its amount («مجاني»); `prominent` puts the total on the orange bar (customer cart), `plain` bold under a rule.
- **Skeleton** with `Skeleton.Block` (a static property, so the story coverage test sees one component): `role="status"`, `aria-busy`, hidden blocks; `motion-safe:animate-skeleton` (keyframes in `styles.css`: opacity to 0.55 over `duration.moment`). The token theme resets Tailwind's `aspect-video`, so `styles.css` adds `aspect-cover` (16:9) and `aspect-dish` (1:1), the photo ratios of brand expression §5.
- **EmptyState:** an icon inside the logo's drop (an inline SVG path), a heading, one line, at most one `Button` (primary when `tone="error"`).
