# packages/design-tokens and packages/core_tokens

What the tokens pipeline does and why (slice D.2; architecture §9.2, §9.5 R1 and R4; brand expression §3, §6, §7). The rules for editing are in each package's `CLAUDE.md`.

## Pipeline

- Sources: W3C DTCG JSON (`$value`, `$type`). `tokens/primitive/color.json` and `foundation.json` (all under the `primitive` key), `tokens/semantic/base.json` (theme-free: space, radius, elevation, duration, easing, font, the type roles per surface, breakpoints, touch target), `semantic/light.json`, `dark.json` and `captain.json` (colours), `tokens/component/button.json`.
- `src/resolve.ts` runs Style Dictionary 5 once per theme: `light`, `dark`, `captainLight` (light plus the captain override) and `captainDark`. The override is a Style Dictionary `source` over an `include`, so it replaces keys without a collision warning. Style Dictionary only resolves references; `src/generate.ts` writes the formats itself, since none of its built-in formats gives the three outputs we need (variables per theme selector, a Tailwind v4 `@theme`, pure-Dart `const` classes).
- Outputs, committed: `generated/tokens.css` (`--fd-*` variables: `:root`, `[data-theme="dark"]`, `[data-surface="captain"]` and the dark captain), `generated/tailwind.css` (`@theme inline` that starts with `--*: initial` and maps semantic names to the variables), `generated/contrast-report.md`, and `packages/core_tokens/lib/src/tokens.g.dart`. The Dart file is written already in `dart format` style, so the generator needs no Dart SDK.
- Drift: `src/tokens.test.ts` renders every output and compares it with the committed file (as `infra/maps/style.json` does), so no step in `verify.mjs` is needed. `scripts/classify-changes.mjs` counts `packages/design-tokens/` as Dart too, so CI checks the Dart output.

## Decisions

- **The Figma file adopted (slice D.3, owner 2026-11-23, version 0.2.0).** The values were measured from the file's nodes through the REST API (`docs/brand/directions.md`). Ground `surface` `#FBF2E7`, raised `#FEFEFE`; all text in the brand blue `#03428E` (8.72:1); muted text is the blue at 75% over the ground, `#416EA4` (4.59 to 5.22:1), since the file's lighter alphas fail 4.5:1; `border` is the blue at 16% `#D3D6D9` (decorative), `border-strong` the blue at 60% `#6688B2` (3.20 to 3.63:1), since the file's 40% input border fails 3:1. Danger is the file's `#BF2929` (5.32:1, white on it 5.89:1).
- **The brand-orange exception.** `primary`, `heading` and `brand` are `#FF6E31` as the file draws them (`primary-pressed` is orange 500 `#EA580C`), in every app the captain's included (owner 2026-11-23), although orange on ivory is 2.52:1 and ivory on orange 2.68:1. `src/contrast.ts` gives those pairs an `exception`; the report marks them «owner exception» and `failing()` ignores only them; a test fails when an excepted pair names a colour outside `ORANGE`. The former accessible orange `#C2410C` (orange 600, slice D.2) stays as an unused primitive.
- **Radii and shape from the file:** sm 8 (add-on cards), md 10 (inputs, small components), lg 15 (cart cards, totals, total bar), xl 30 (banner), full (buttons, tags, icon circles). `radius.xs` (4) is deprecated for one release. `size.control` is the 50 px button height and icon-circle diameter; the Button is a pill at that height. `elevation.offset` is the file's flat shadow: `#FD6425` (orange 450), 7 px down, no blur.
- **Status colours** as the brand expression's candidates; all pass. The captain override darkens the muted text (neutral 700) and the success, warning and danger text (green 800, amber 800, red 800) to reach 7:1; info stays the brand blue.
- **Alert** (restaurant tablet and panel): red 800 `#8C1530`, 8.90:1 on ivory, white on it 9.27:1.
- **Chart colours:** the first candidates (olive `#6B7A1F`, pink `#DB2777`) failed: orange and olive were 0.9 apart (CIEDE2000) under protanopia. A darker olive `#4D5A12` and a deeper pink `#BE185D` give at least 11.97 under every simulation (the test asks for 11) (Machado 2009, severity 1). The orange is orange 500 `#EA580C` (3.42:1), since the brand orange is below 3:1.
- **Borders:** `border` is for decorative dividers and has no contrast pair (WCAG 1.4.11 covers component boundaries); `border-strong` is the control boundary at 3:1.
- **Disabled** colours have no pair: WCAG exempts inactive controls.
- **Type roles** carry size, line height (text 1.6, headings 1.3, numbers 1.2) and weight: caption, secondary and body 400, subtitle 500, title, large title and number 700.
- **Tailwind breakpoints** carry literal values: a media query cannot read a CSS variable.
- **Tabular digits:** `scripts/font-metrics.mjs` measures CoFo 400/500/700 with fontkit and writes `packages/design-tokens/font-metrics.json` (inside the package, so a change to it runs the checks): 650 units for every digit with `tnum` in all three weights, proportional widths of 514 to 703 without it. `scripts/font-metrics.test.mjs` checks the widths and the SHA-256s against the fonts manifest, and remeasures when `.fonts/` is present.

## The Design System and the Guide (D.4)

Two private artifacts (architecture §9.8) are built from this package and published by Claude with the Artifact tool; they have no API for CI, so a sync is a Claude Code step (`CLAUDE.md` «Sync»). Their links live in Claude's memory.

- **Tokens:** `src/design-system.ts` renders `generated/design-system.json` in the Design System type's `tokens.json` shape, one of `OUTPUTS`, so the drift test covers it. Colours are the semantic layer only, per theme (light first, then dark, captain light, captain dark), as hex. Families are lists: `spacing` (`space-*`), `radius`, `shadow` (`elevation-*` as CSS shadows), `size` (the cover binds its pills and circles to `size-control`); the type groups are Phone, Panel and Captain with styles `<surface>-<role>`. Every token's `usage` is its `$description`, so a token without one fails the render. Durations and easing are left out: the type has no motion family. `meta` holds no sha or date, so the file renders the same twice.
- **The system's files:** `src/design-system-build.ts` writes `.design-system/system/` (ignored: it carries the licensed fonts): `project/` with the tokens, the hand-written brand book `design-system/README.md` (English with Arabic examples, from `docs/brand/`), the cover `design-system/Cover/preview.html`, the CoFo 400, 500 and 700 files (checked against `docs/brand/fonts-manifest.json`; owner, 2026-11-23: not YR-Speed or Emad-Diana) and a README per asset group; and `uploads/` with the logo and app icon SVGs, which go to the asset store. The `broken-edges` icons stay out until the owner names them. `--blobs` writes the index from the upload replies, with `"editing": "code"` so the page is read-only; `created` is kept across syncs, and each record's `size` is the size the store reported, which differs from the file on disk.
- **The guide:** `src/guide.ts` writes `.design-system/guide/`: the canvas index, which installs the system under `ds/fox-drop/` (its `tokens.json` copied server side from the system), and six RTL artboards drawn from the resolved tokens: Main, Colour (every semantic colour per theme and the light and captain light contrast pairs of `src/contrast.ts`), Type, Foundations, Shapes and Rules, the last read from the §9.5 table so it never drifts. The config file holds the system's link, `created` and the CoFo urls uploaded to the canvas; it stays outside the repository.

## Icons (D.5)

The first 44 line icons of brand expression §10, on the grid of architecture §9.4 (R8).

- **Sources:** `icons/<name>.svg` and the manifest `icons/icons.json` (`{name, group, mirror, description}` in §10's order and six groups). `src/icons.test.ts` checks every file against the grid (root attributes, geometry-only children, 2 decimals, the live area 2..22 sampled through `src/icon-geometry.ts`, which reads the path commands M L H V C S Q T A Z), the manifest one to one with the files, the group counts and the mirror set (`back`, `car`, `motorcycle`).
- **Drawing language:** measured from the Figma file's own icons through its REST API (owner's request, 2026-11-23): outlined strokes of about 2 at 24, round caps and joins, plump soft shapes, often one continuous line, about 65% of the circle they sit in. Kept from it: the basket cart, the scooter with a box and speed lines, the bell opening onto a dot, the heavy back chevron, the handled bin, the flame with % for a discount. Added: one small detail per icon where it reads (a glint, steam, sound waves, a wavy stroke). The drop appears only in `drop-pin` and `map` (expression §2).
- **Outputs** (in `OUTPUTS`, so the drift test covers them): `src/icons.ts` turns every shape into path data (circles, ellipses and rects become arcs; path data stays as authored). Web: `generated/icons.ts`, exported as `@fox-drop/design-tokens/icons` (`icons`, `IconName`, each `{d, mirror}`). Dart: `packages/core_tokens/lib/src/icons.g.dart` (`FoxIcons.<name>`, `FoxIcons.all`, `FoxIconData(paths, mirror:)`), written in `dart format` style. Named `Fox*` like `FoxColors`.
- **Sizes:** `size.icon-sm` 16, `size.icon-md` 24, `size.icon-lg` 32 (0.3.0).
- **The sheet:** `src/icon-sheet.ts` draws «Icons — batch 1» on the Component proposals canvas (every icon with its Arabic label, active state, three sizes, the mirrored three in LTR and RTL, a grid overlay). The owner approved it on 2026-11-23, open to edits when the screens are built.
- **Design System:** an `Icons` asset group (tile `m`) with a README of the grid rules.

## Icon set v4 Madar (D.5b)

The owner replaced the D.5 drawings with set v4 "Madar" on 2026-11-24 (architecture §9.4). The geometry was drawn outside the repository; a one-off converter wrote the 47 SVGs, and from then on the SVGs here are the source.

- **Sources:** each element is one `<path d>` with `data-role`, a detail's `data-knock` and the flags `data-accent`, `data-fill`, `data-open`, `data-halo`. `src/icons.test.ts` checks the root (stroke 1.5), paths only, the roles, a body (except the 8 bare glyphs) and an accent per icon, 2 decimals, the live area, the manifest and the mirror set.
- **Import fixes**, too small to see, for geometry the grid refuses: `bell`'s clapper moved up from y 22.1 to 22, `route`'s pin moved 0.1 left so it ends at x 22, `restaurant`'s awning arcs `A2.375` written `A2.38`, and `retry`'s arrowhead (it reached y 1.09) has both arms shortened by the same factor so the tip sits at y 2.
- **The bake** (`src/icon-bake.ts`, dev dependency `canvaskit-wasm` 0.42.0, used at generate time only). Flutter's Canvas has no SVG masks or dash offsets, so the three styles that need them are computed once, with Skia, the engine Flutter itself draws with:
  - **Broken** cuts the primary body (first non-accent body, else the first) at its point nearest (22, 2), 3.75 of path length (2.25 plus the round caps). On an open body the bite slides to the nearest point where a whole gap fits with a 1.5 stub at each end (owner, 2026-11-24): `bell`, `restaurant` and `share` have their bite at the end of the line otherwise. The bite is measured at resScale 100: at 1, Skia measures curves only to about 0.3 on the 24 grid.
  - **Bold and Bold Duo** are fills at each weight in `WEIGHTS` (1.5, 1.75; a bodiless glyph 1.4 times that), built with path ops as `template.html` built them with masks: the bodies' fill and stroke, minus the `in` details (Bold only) and the halos (stroke + 2.5), plus the halo bodies, plus the details. Bold Duo keeps one layer per body, faded unless it is the accent.
  - Every result goes through simplify and `makeAsWinding` (nonzero fill on both platforms). The path data is written from `toCmds`, not `toSVGString`: Skia's round caps are conics, which `toSVGString` flattens into one coarse quad each (0.16 off on the grid); each becomes the cubic with handles at 4w / 3(1 + w). Numbers are rounded to 2 decimals. The bake is deterministic, and CI's drift test compares it on Linux with what Windows committed.
  - CanvasKit 0.42's types declare `makeSimplified`, but only the binding `_makeSimplified` ships; `clean()` calls that.
- **Outputs:** web `icons.<name>` = `{elements: [{d, accent}], broken, bold, boldDuo, mirror}` at 1.5 only (no web surface is the captain's); Dart `FoxIconData(elements:, broken:, bold:, boldCaptain:, boldDuo:, boldDuoCaptain:, mirror:)` with `bold(FoxIconWeight)` and `boldDuo(FoxIconWeight)`, and the enum `FoxIconWeight` (phone 1.5, captain 1.75), the values of the `icon-stroke.*` tokens (a test checks they agree). Sizes: `generated/icons.ts` 130 KB, `icons.g.dart` 231 KB.
- **The sheet:** `icon-sheet` adds «الأنماط الستة», every icon in the six styles (`styleMarkup` in `src/icons.ts`); the other review sheets draw their icons at stroke 1.5.
- **Contrast:** `brand` on `surface`, `surface-raised` and `primary-subtle` (the Brand Duo accent), under the orange exception: 2.52, 2.77 and 2.45.

## Interaction states, R10 (D.6)

Version 0.5.0 (owner, 2026-11-24). The 0.4.0 hover, a mix of fill and pressed, measured ΔE2000 3.3 on primary and 1.3 on ghost and was not seen. `src/state-sheet.ts` drew three systems live on the Component proposals canvas («Interaction states — one system»: an ink layer, brand tonal steps, tonal steps with motion); the owner picked **brand tonal steps** without motion.

- **Triples** (`STATE_TRIPLES` in `src/contrast.ts`): `primary` → `primary-hover` (orange 550) → `primary-pressed` (orange 600); `danger` → `danger-hover` (red 700) → `danger-pressed` (red 900; captain red 900 → red 950); `surface` → `surface-hover` (blue 50) → `surface-pressed` (blue 100); `surface-raised` → `surface-raised-hover` (blue 100) → `surface-raised-pressed` (blue 200; captain blue 100). `border-hover` (blue 500) is the outline under the pointer. White needs the deeper blue: blue 50 on it is only ΔE 4.7.
- **The test** (`tokens.test.ts`, «makes every hover and press visible»): in the pointer themes (light, dark) hover ≥ `MIN_HOVER` 8 from rest and pressed ≥ `MIN_PRESS` 5 beyond hover; in the captain themes (touch, no hover) pressed ≥ 8 from rest.
- **Contrast:** the state grounds (`STATE_BACKGROUNDS`) need only `on-surface` (4.5, captain 7) and the focus ring, since they are transient; `surface-pressed` therefore left `BACKGROUNDS`, and a selected item is designed with accent. `on-danger` on `danger-hover` and `danger-pressed`; `on-primary` on `primary-hover` under the orange exception (`ORANGE`).
- **Changed values:** `primary-pressed` orange 500 → 600; `surface-pressed` neutral 100 → blue 100; `button.danger.background-pressed` is `danger-pressed`, no longer `alert`, so the captain's pressed danger now shows a step.

## The Flutter cards (2026-11-24, owner)

The owner asked for every component in the Design System, the Flutter ones too. `core_ui`'s golden test `test/golden/design_system_cards_test.dart` draws one 720-wide image per component (`test/golden/goldens/design-system/Fox*.png`, phone theme on the apps' ground, the captain theme where it differs) and `packages/core_ui/design-system/cards.json` names each card, its group («Flutter · Forms» and so on), a summary and its web twin. `design-system-build.ts` uploads the images as the asset group Flutter; the `--blobs` pass also writes each card's README and a preview that shows its image, as tall as the image at 720. ## Motion tokens (0.11.0, D.11b)

`motion.pulse.*` and `motion.mark-fill.*` are numbers and durations, not curves: the loader and the tracking pulse compute their frames from them (`FoxMotion` in Dart; `--fd-motion-*` in CSS, which the web's keyframes cannot read, so ui-web's test checks the shares written in `theme.css`). The Dart output writes a `duration` token as `Duration` and every other one as `double`.

## Left out

The `tnum` feature as a token (D.6 and D.7 set `font-variant-numeric: tabular-nums` or `FontFeature.tabularFigures()` on the number role and on money, timer and table text); real dark values; wiring the theme into the web apps (D.6) and Flutter (D.7); components in the Design System (D.6); publishing the artifacts from CI; font subsetting and size budgets; map style tokens (D.3); densities (the panel scale covers the compact one for now). Icons: the `Icon` components (D.6 `ui-web`, D.7 `core_ui`); the second batch (expression §10); filled or duotone variants and the Figma file's orange accent layer (the bell's dot, filled stars), which R8 forbids today and waits for the owner; an icon font.
