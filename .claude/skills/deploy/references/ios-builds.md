# Staging iOS builds

Read when the task needs it; the short rules are in `SKILL.md`.

## The staging iOS builds (slice 2.46)

Owner decisions 2026-11-20: no Apple Developer account yet; GitHub Actions on macOS and TestFlight once it exists; Android's bundle IDs (`com.foxdrop.customer.staging`, `com.foxdrop.captain.staging`). Every pull request that touches a Flutter app builds both apps unsigned (`ios-release`, `macos-26` for Xcode 26); every merge to `main` runs `staging-ios`, which stays skipped until the variable `STAGING_IOS_TEAM_ID` is set. It builds the staging flavor (`flutter build ios --config-only`, then `xcodebuild archive` with automatic signing through an App Store Connect API key) and uploads it to TestFlight (`-exportArchive` with `destination: upload`), build number the run number. The repository is public, so the macOS minutes cost nothing.

The owner's steps, once the account exists (an organisation account needs the company's D-U-N-S number):

1. **Apple Developer › Certificates, Identifiers & Profiles › Identifiers:** the App IDs `com.foxdrop.customer.staging` and `com.foxdrop.captain.staging` with the capabilities **Push Notifications**, **Time Sensitive Notifications** and **App Attest**.
2. **App Store Connect › Apps:** a new app for each bundle ID (its name, primary language Arabic, the SKU), so TestFlight takes its builds. **Users and Access › Integrations › App Store Connect API:** a team key with the **App Manager** role; download the `.p8` once.
3. **GitHub › Settings › Environments › staging:** the variables `STAGING_IOS_ASC_KEY_ID` and `STAGING_IOS_ASC_ISSUER_ID` and the secret `STAGING_IOS_ASC_KEY` (the `.p8` in base64: `base64 -i AuthKey_XXXX.p8`). Keep the `.p8` in the password manager and delete the file. Then **Settings › Secrets and variables › Actions › Variables** (the repository's, since a job's `if` reads no environment variable): `STAGING_IOS_TEAM_ID`, the team's 10-character ID (Membership). Set it last: it turns the job on.
4. **Push (APNs through FCM, architecture §8.1):** **Certificates, Identifiers & Profiles › Keys:** a key with **Apple Push Notifications service (APNs)**; download the `.p8`. Firebase › **Project settings › Cloud Messaging › Apple app configuration:** upload it with its key ID and the team ID for each iOS app.
5. **Firebase (the `foxdrop-staging` project of `app-check.md`):** add two iOS apps with the bundle IDs above (skip `GoogleService-Info.plist`: it never enters the repository). The variables `STAGING_FIREBASE_CUSTOMER_IOS_APP_ID` and `STAGING_FIREBASE_CAPTAIN_IOS_APP_ID` (`1:<number>:ios:<hex>`) and the secret `STAGING_FIREBASE_IOS_API_KEY` (Google Cloud › Credentials, «iOS key (auto created by Firebase)»). **App Check › Apps:** register each iOS app with **App Attest** (and DeviceCheck for older phones). Without the app ID the build has no push and no App Check, and warns.
6. **TestFlight:** add the testers (internal testers are the team's users; external ones need a beta review the first time); each installs TestFlight and the build.
7. **The captain's background location (architecture §22 item 8):** `flutter_background_geolocation` 5 needs its licence on iOS too; the key for `com.foxdrop.captain.staging` is the secret `STAGING_CAPTAIN_BGGEO_LICENSE` the APK uses (one app ID, both platforms, as Transistorsoft's dashboard says), passed to Info.plist's `TSLocationManagerLicense` as the build setting `FOXDROP_BGGEO_LICENSE`. Without it the TestFlight build tracks through `geolocator`'s background updates.
8. **Critical Alerts (K15, owner decision 2026-11-20: apply now):** request the entitlement for `com.foxdrop.captain` and `.staging` at developer.apple.com/contact/request/notifications-critical-alerts-entitlement (the reason: couriers must hear a delivery offer within seconds even on silent; the offer lasts under a minute). Until Apple answers, offers are time-sensitive with the 30-second sound and the device check asks to keep the ring switch on. Once granted: add `com.apple.developer.usernotifications.critical-alerts` to `apps/captain/ios/Runner/Runner.entitlements` and the capability to the App IDs (a pull request), then set `APNS_CRITICAL_ALERTS=true` in the server's `.env` and deploy: the offers' pushes become critical, and the app already asks for the permission.
