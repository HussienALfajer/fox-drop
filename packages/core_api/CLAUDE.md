# packages/core_api

The Dart client of the FOX DROP API for the three Flutter apps (architecture §5.3, §11.2; E6).

## Contents

- `lib/`: generated by `openapi-generator` (`dart-dio`, `built_value`) from `packages/api-schema/openapi.json`, then by `build_runner` (the `*.g.dart` files). One API class per route group: `CoreApi().getAdminApi()`, `getMerchantApi()`, `getCaptainApi()`, `getCustomerApi()`.
- `pubspec.yaml`, `analysis_options.yaml`, `.openapi-generator-ignore` and `test/`: written by hand. The ignore file keeps the generator out of everything but `lib/`.

## Rules

- Never edit `lib/` by hand. Change the server, run `pnpm generate:api` from the repository root (it needs Java 11 or later) and commit what changed. `pnpm verify` fails when the committed `lib/` is stale.
- `analysis_options.yaml` switches off, for the whole package `test/` included, the style rules the generator's templates break and one warning, `unused_import`. Do not add a rule there to hide an error or another warning from a real change: fix the server's document instead.
- When a generated file imports a new package, add it to `pubspec.yaml` with an exact version.
- `test` and `build_runner` share one resolution with the Flutter apps (the pub workspace), and the pinned Flutter's `flutter_test` pins `test_api`. So `test` stays on the version that uses that `test_api` (1.31.1 for Flutter 3.47.9), and `build_runner` on one that accepts that `test`'s `analyzer` range; both move with Flutter (`renovate.json`).
- The auth interceptor lives in `core_auth` (`AuthInterceptor`), next to the session it renews (slice 1.14b); the apps add it to their client. The `Idempotency-Key` and app-version headers of §11.2 come with the slices that need them. `pnpm generate:api` replaces all of `lib/`, so the first of those slices moves the generated code into a folder of its own before adding hand-written code.
