# packages/design-tokens

The design tokens of every app (architecture §9.2, §9.5 R1 and R4; brand expression §3, §6, §7). W3C DTCG JSON under `tokens/`, resolved by Style Dictionary (`src/resolve.ts`) and written by `src/generate.ts`. What was built and decided: `docs/code/packages/design-tokens.md`.

## Rules

- **Edit the JSON under `tokens/`, never an output.** Then run `pnpm --filter @fox-drop/design-tokens generate` and commit what changed: `generated/tokens.css`, `generated/tailwind.css`, `generated/contrast-report.md` and `packages/core_tokens/lib/src/tokens.g.dart`. A test fails when a committed output differs from a fresh render.
- **Three layers.** `tokens/primitive/` holds raw values under `primitive.*`; only semantic tokens reference them, and no output exports them. `tokens/semantic/` holds meanings; `tokens/component/` holds one component's tokens, referencing semantic tokens only. Screens use semantic names only.
- **Every semantic colour has its dark slot:** a key added to `semantic/light.json` goes into `semantic/dark.json` too (a test compares the key sets). Until dark mode is designed, the dark value copies the light one (owner, 2026-11-22). The captain override has its dark slot too: `semantic/captain.json` and `semantic/captain-dark.json` hold the same keys, existing keys only.
- **A new foreground or background colour gets its contrast pair** in `src/contrast.ts` with its target: 4.5:1 text and filled controls, 3:1 control boundaries, focus ring and icons, 7:1 captain text and alerts. Only the brand orange (`#FF6E31`: `brand`, `primary`, `primary-pressed`, `heading`) may sit below target, under the owner's exception of 2026-11-23 (architecture §9.5 R4); its pairs carry `exception`, and a test keeps the exception to those tokens. Body text, numbers and prices stay blue or near-black.
- **Chart colours** stay at 3:1 on the surfaces and at CIEDE2000 ≥ 11 from each other under protan, deutan and tritan simulation (`src/tokens.test.ts`).
- **Governance (§9.2):** bump `version` in `package.json` and add a `CHANGELOG.md` entry for every token change. To remove a token, first mark it `"$deprecated": "<what replaces it>"` for one release.
- **Sync (§9.8)** after a token, brand book or cover change: `pnpm --filter @fox-drop/design-tokens design-system`, upload `.design-system/system/uploads/*` to the Design System with the Artifact tool, save `{created, assets: {"<Group>/<file>": {blob, size}}}` from the replies, rerun with `--blobs <file>`, then publish `project/` with `root` and the index as `file_path`, in one call. Then `guide --config <file>` and publish `.design-system/guide/` (its `ds/fox-drop/tokens.json` copied server side from the system: `read` the published copy first, or the publish is refused). The links live in Claude's memory, never in the repository. Never edit either artifact on its page.
- Tailwind breakpoints carry literal values (a media query cannot read a variable); every other Tailwind entry points at a `--fd-*` variable.
